# Threat model — laboratory reference

Assets: trusted public keys, signed scopes, policy state, permits and evidence digests. Trust boundaries: untrusted agent input vs trusted host, organization isolation, public vs private, crypto ecosystem boundary. Threats: forged identity, replay, scope substitution, stale authorization, policy bypass, compromised administrator, ledger rewrite, lost device, network partition. Controls: strict input validation, cryptographic verification where applicable, deny precedence, bounded expiry and independent verification. No persistent append-only store, external witness, Merkle inclusion proofs, trusted timestamp, tenant authorization or production immutability. A trusted externally retained checkpoint is necessary to detect history replacement. Residual risk: a compromised trusted host can bypass this local reference. No production use before independent threat modeling and acceptance.
